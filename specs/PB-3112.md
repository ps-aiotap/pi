## Summary

For check template **"Check on Top and Stub on Bottom 908"**, amounts on the printed check stub do not match the descriptions / do not sum to the check face amount (**expected total 50,000** per reporter). Template 908 surfaces multi-distribution ledger lines on the stub; the bug is in PHP stub payload mapping, not template-specific branching.

## Reproduction / symptoms

### Preconditions

- Checkbook using template **Check on Top and Stub on Bottom 908**
- Bank/Cash check with **multi-distribution** ledger lines whose absolute amounts sum to the check amount (e.g. 50,000)

### Steps

1. Open Bank/Cash → select the check transaction(s) → Print Checks.
2. Ensure **Print Vouchers on All Checks** is checked.
3. Print / Print Preview with template 908.
4. Sum stub ledger line amounts vs check **Amount**.

### Symptom check

- **Expected:** Stub ledger lines (plus Others) sum to check Amount (50,000).
- **Actual:** Stub amounts / mapping against descriptions do not match; summation ≠ 50,000.

## Root cause (code)

1. `getCheckPrintData` `GROUP_CONCAT` of `bankmultidistributution` had **no ORDER BY** and **included the bank balancing row** (`columnvalue='bank'`).
2. `printvouchers.phtml` assumed index 0 was bank/total and emitted `txt_ledgeramount0`, which **`getCheck` never reads** (only `1`–`5`). If bank is not first, a real ledger is dropped or bank 50k appears on the stub.
3. Comma-formatted amounts (`number_format`) made `txt_otherledgeramount > 0` brittle for CHECKPRINT.

Hotspots:

- `app/common/transaction/AVBankcashTransaction.php` `getCheckPrintData`
- `app/modules/avbankcash/views/index/printvouchers.phtml`
- `app/modules/wealth/controllers/IndexController.php` `getCheck`
- `app/modules/avbankcash/controllers/PdfController.php` (preview mirror)

## Proposed fix

1. Exclude `columnvalue='bank'` from stub `GROUP_CONCAT`; order by `st.id`.
2. Chunk ledger lines by **5**; emit `txt_ledgeramount1`–`5` + Others; use decimal amounts without thousands separators.
3. Strip commas in `getCheck` / PdfController before CHECKPRINT JSON.

## Acceptance criteria

- For multi-dist check totaling 50,000, stub LedgerAccountAmount1–5 + Other equals 50,000 (abs).
- Bank balancing row never appears as a stub ledger line.
- Print Preview and Print Checks stay consistent.
- Single-ledger checks unchanged.
